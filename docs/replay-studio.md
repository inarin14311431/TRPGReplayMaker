# Replay Studio 利用ガイド

## 全体の流れ

1. Discord Botをサーバーへ追加し、参加者全員の録音同意を取る。
2. ボイスチャンネルで /join を実行し録音。終了時は /leave。
3. Web管理画面の Replay studio で録音を選ぶ。
4. アクトタイトル、TRPGシステム、固有名詞辞書、PL名とキャスト名を設定し、保存。
5. 文字起こしを発言単位に校正。原文は保持され、修正・非表示指定は別テーブルに保存。
6. シーンの区切りを追加。長いセッションは『長いログを自動分割』で概ね12,000文字ずつ区切る。
7. 個々のシーンでAI原稿生成、または『未生成の全シーンをAI生成』で連続処理。
8. AI原稿を見直し、本文を手動修正して保存。
9. 『原稿を保存 (.md)』で完成用原稿、会話ログ(.md)で発言順の記録、編集データ(.json)で原文と修正履歴を取得する。

## 生成モード

- 会話再現（dialogue）：GMとキャストの発言を中心に記録。
- ハイブリッド（hybrid）：PL会話や判定も必要に応じて残す。
- 小説調（novel）：地の文を加えた編集を依頼。ただしログにない出来事は創作させない。
- 誤認識した固有名詞は辞書だけに頼らず、発言編集画面から修正する。

## 長いセッションの取り扱い

- 一覧および発言編集は80発言単位のページングで読み込み、大量ログをまとめて画面へ渡さない。
- AIへ渡す原文は1シーン上限24,000文字。超える場合は分割して再実行する。黙って途中を省略しない。
- 一括AI生成は未生成シーンだけを順番に処理し、個々の成功分を即保存する。途中失敗したシーンは再実行可能。
- 一括処理はブラウザから順番にAPI呼び出しをするため、その間は画面を開いたままにする。
- AIモデルによってはAPIの利用料金が発生する。使用するAIプロバイダーはダッシュボードの設定に依存する。

## データ保全・安全

- 原文はSQLiteのutterancesに保持。修正はreplay_line_edits、シーンと原稿はreplay_scenesに保存する。
- Markdown原文の行末には出典の発言IDが含まれる。再生可能な音声を保持している期間は原音声と照合する。
- AI文章は推測や誤認識の可能性があるので、人間が確認してから公開する。
- 編集は管理者権限が必要。実セッションの生音声・ログ・SQLite DB・APIキーを公開GitHubへアップロードしない。
- 12時間連続録音の実機検証は未実施。録音が停止した間の音声は回復不可。

```bash
npm --prefix packages/trpg-replay test
```

GitHub Actionsの Node tests / STT sidecar tests / Web dashboard build も確認する。

## 元音声の照合

個別発言の「修正」を開くと音声プレーヤーが表示されます。発話ターンごとのPCMをサーバーがWAVとしてストリーミングし、途中からのシークにも対応します。元PCMが既定の保存期間を過ぎた場合や録音に失敗した場合は再生できません。再生にはダッシュボードへのログインが必要です。
